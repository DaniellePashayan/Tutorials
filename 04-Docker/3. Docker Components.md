# Docker Fundamentals

1. DockerFile ("The Recipe")
This is a text file that contains a list of steps for creating your application environment. For example, it tells the container: "Start with Ubuntu, install this version of Python, install that version of UV, copy these scripts into this directory, and then run this command".

2. Docker Image ("Cake Mix")
A docker image is the output of running the DockerFile and is a 'ready to be distributed' snapshot. It contains the exact OS, libraries, and code from a point in time. 

3. Docker Container ("The Cake")
The living, breathing environment that is the result of starting the image. It is the isolated box running on the host that executes the software. It can be started, stopped, restarted, or deleted at any time and in seconds. Containers are temporary. Once a container is stopped or deleted, any data generated inside of it is also deleted (see "Volumes" for further detail)

4. Docker Compose ("The Bakery")
Compiles multiple containers into a "stack" that can be deployed at once. You can have one container running the API, another container running the website, and another container running the database. 

5. Volumes
Volumes map to the host's file system and allow for the persistence of data outside of the container. It is a one way track where the container can access ONLY its mapped volume and nothing more. However, the host can see the data from all container volumes.
